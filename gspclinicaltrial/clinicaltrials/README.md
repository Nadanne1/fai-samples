# TrialMatch360 Dashboard

Clinical trial recruitment dashboard for importing studies, screening connected patient populations, explaining eligibility decisions, and tracking recruitment performance.

---

## Architecture

```
Browser (React + Vite)
  → CloudFront
      ├── /api/*  → API Gateway HTTP → Lambda (FastAPI + Mangum)
      │                                    ├── HealthLake FHIR R4
      │                                    ├── DynamoDB (audit, trials, rules)
      │                                    ├── Bedrock (Claude Haiku — screening AI)
      │                                    └── ClinicalTrials.gov API v2 (proxy)
      └── /*      → S3 (React SPA)
```

### Key AWS Resources

| Resource | Name / ID |
|---|---|
| Lambda | `clinical-trial-screening` (Python 3.13, x86_64) |
| HealthLake | datastore ID from `HEALTHLAKE_DATASTORE_ID` env var |
| DynamoDB | `TrialAuditLog`, `TrialProtocolConfig`, `TrialScreeningRules` |
| Bedrock model | `us.anthropic.claude-haiku-4-5-20251001-v1:0` |
| S3 frontend bucket | `clinical-trial-screening-frontend-{account-id}` |

## Setup (first time)

```bash
cd clinicaltrials
cp .env.example .env
# Set HEALTHLAKE_DATASTORE_ID in .env — that is the only required value
set -a; source .env; set +a
bash infra/setup.sh
```

Optional flags:

```bash
bash infra/setup.sh --with-patients    # also import FHIR sample data into HealthLake
bash infra/setup.sh --with-agentcore   # also deploy AgentCore MCP gateway
```

After setup, run locally:

```bash
# Backend
uvicorn app:app --host 0.0.0.0 --port 8000 --reload

# Frontend (separate terminal)
cd dashboard && npm install && npm run dev   # http://localhost:5173
```

The Vite dev server proxies `/api/*` to `localhost:8000` automatically — no extra config needed.

## Deploy to AWS

```bash
cd clinicaltrials
bash infra/deploy.sh --code-only
```

Builds Lambda zip from source, syncs React build to S3, invalidates CloudFront. **Always use the script — never `aws lambda update-function-code` directly.**

## Environment Variables

All config is in `config/settings.py`. The only value you need to set:

| Variable | Description | Default |
|---|---|---|
| `HEALTHLAKE_DATASTORE_ID` | HealthLake datastore ID | *(required)* |
| `AWS_REGION` | AWS region | `us-east-1` |
| `CLINICAL_TRIALS_API_KEY` | API key for AgentCore MCP tool auth | *(only needed for AgentCore deploy)* |

All DynamoDB table names and SQS queue names have defaults that match what `setup.sh` creates — no need to set them.

**Import to a new datastore:**

```bash
# Import all clinical data (not insights)
python infra/import_sampledata.py

# Import clinical data + cached insights snapshot
python infra/import_sampledata.py --with-insights

# Dry-run (print counts, write nothing)
python infra/import_sampledata.py --dry-run
```

**Re-export from live datastore:**

```bash
python infra/export_sampledata.py
```

## Patient Insights

AI patient insights are generated by Amazon Connect Health and stored as FHIR `DocumentReference` resources (type code `ai-clinical-trial-insights`) directly in HealthLake. The API route `GET /api/patient/{id}/insights` reads the current `DocumentReference` for that patient — there is no separate database or cache.

**How to refresh insights:**

```bash
cd clinicaltrials
set -a; source .env; set +a

# Refresh all patients (concurrent, ~30-40 min for 48 patients)
python infra/refresh_insights.py

# Refresh a single patient
python infra/refresh_insights.py --patient-id 030f01b8-1e8b-499a-b

# Increase parallelism (default is 8)
python infra/refresh_insights.py --batch-size 16

# Preview which patients would run without executing
python infra/refresh_insights.py --dry-run
```

**What the script does per patient:**
1. Starts a Connect Health `PRE_VISIT` insights job pointed at the HealthLake FHIR endpoint
2. Polls until the job succeeds (polls every 15 s, timeout 15 min)
3. Downloads the output JSON from S3 (`clinicaltrials360-insights-output`)
4. Marks the previous `ai-clinical-trial-insights` DocumentReference as `entered-in-error`
5. Writes a new DocumentReference with the fresh insights (base64-encoded JSON)

The API route reads the latest `current` DocumentReference automatically — no deploy or cache flush needed after a refresh.

Results are logged to `infra/refresh_insights_results.json`.

## Seed / Setup Scripts

One-time setup scripts in `infra/`:

```bash
cd clinicaltrials

# Seed trial protocol configs into DynamoDB
python infra/seed_trials.py

# Seed synthetic analytics records
python infra/seed_analytics.py

# Import sample FHIR data into HealthLake
python infra/import_sampledata.py
```

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/` | Health check |
| GET | `/api/patients` | Patient list from HealthLake |
| GET | `/api/queue` | Screening queue depth |
| GET | `/api/trials` | Configured trials |
| GET | `/api/trial/{id}` | Trial detail + screenings |
| GET | `/api/trial/{id}/healthlake-mapping` | FHIR resource map |
| GET | `/api/patient/{id}` | Patient FHIR detail |
| GET | `/api/patient/{id}/insights` | AI patient insights |
| GET | `/api/patient/{id}/trial-history` | Screening history |
| POST | `/api/chat/start` | Run AI eligibility screening |
| GET | `/api/analytics` | Aggregate screening analytics |
| GET | `/api/ctg/search` | Proxy search to ClinicalTrials.gov |
| GET | `/api/ctg/study/{nctId}` | Fetch study detail from CTG |
| POST | `/api/ctg/import` | Import a trial from CTG |
| GET | `/api/screening-rules` | List screening rules |
| POST | `/api/screening-rules` | Create screening rule |
| PUT | `/api/screening-rules/{id}` | Update screening rule |
| DELETE | `/api/screening-rules/{id}` | Delete screening rule |
| POST | `/api/screening-rules/reset` | Reset to defaults |
| POST | `/screen` | AgentCore: screen patient (MCP tool) |
| GET | `/escalations` | AgentCore: list escalations |
| POST | `/trials` | AgentCore: configure trial |
